# Charles Trading Desk (Operator Console)

## Purpose

The Charles Trading Desk is the local operating surface for the research system. It combines:

- validated aggregate monitoring for workflows, sources, evidence, reports, readiness, and safety;
- a bounded architecture map generated by `scripts/agent_context.py`;
- six fixed offline diagnostic actions with immutable, hash-bound receipts;
- a local operator instruction queue for later human or agent review;
- the receipt-checked morning report, rendered from already-written local artifacts;
- a separately labeled, read-only post-Morning engineering audit projection;
- two read-only desk feeds projecting the append-only research ledger and trading journal
  (`operator_console_policy/1.3`).

It is not a trading terminal. It has no order, account, position, live-price, model, broker, shell,
strategy-change, or risk-limit authority. Every investment decision and order remains manual.

The service, LaunchAgent, and scripts keep their `operator_console` / `com.charles.trading.console`
names; "Charles Trading Desk" is the interface built on top of them.

## Launch

For full desktop access, install **Charles Pulse** once:

```bash
bash scripts/install_charles_pulse_app.sh --confirm
```

This places `Charles Pulse.app` in `~/Applications`, adds a visible `Charles Pulse.app` launcher to
the Desktop, opens the complete native-sized control center, adds a Dock icon, and keeps a waveform
shortcut in the macOS menu bar. The desktop window contains the full **Today**, **Research**,
**History**, **Checks**, and **System** views plus the standalone morning-report pages; local
report links stay inside the app. Double-clicking the Desktop launcher always brings the window
forward. Closing the window hides it; use the Desktop launcher, Dock icon, or menu-bar icon to
bring it back.

The menu-bar command **Switch to Compact Pulse** changes the same app into the 420-pixel quick-glance
display. That compact mode refreshes validated local status every 15 seconds, shows the five-stage
daily delivery path and latest receipt-checked Morning status, and can switch back to the full
control center. Both modes remain loopback-only with execution disabled.

The full-console launch path is to double-click either artifact in Finder:

- `app/Charles Trading Console.app`
- `Charles Trading Console.command`

Both call `scripts/open_operator_console.sh`. The launcher checks the bounded health contract,
repairs only the dedicated `com.charles.trading.console` LaunchAgent when needed, verifies the
loopback service again, and opens:

```text
http://127.0.0.1:8787/
```

CLI equivalents:

```bash
bash scripts/open_operator_console.sh
bash scripts/install_operator_console.sh --status
bash scripts/install_operator_console.sh --confirm
```

The app bundle contains no service logic or secrets. It is a small local launcher so the repository
remains the single source of truth.

Charles Pulse uses the same service and projection. Its tracked source bundle is
`app/Charles Pulse.app`; the installer binds the installed copy to this project directory without
copying credentials or project data into the app. Read-only status and removal commands:

```bash
bash scripts/install_charles_pulse_app.sh --status
bash scripts/install_charles_pulse_app.sh --uninstall
```

Uninstall moves the app to Trash so it remains recoverable.

## Views

The desk has five hash-routed views. Views live in the URL hash (`#/desk`, `#/system/safety`) so
browser refresh and back/forward keep the operator's place; the server itself only serves `/`,
`/reports/morning*`, `favicon.svg`, and `assets/*`. Legacy targets from the previous four-view
console (`today`, `evidence:sources`, `map`, …) are translated so old receipts and copy keep
working. Digit keys `1`–`5` jump between views when no field is focused.

- **Today**: a session board laid out like a trading desk. The persistent top strip carries the
  target session stamp, PT/ET clocks, market phase, and three independent authority LEDs —
  `RES` (research authority from the receipt-checked report), `BUY` (manual-proposal gate) and
  `EXEC` (permanently OFF) — never inferred from one another (CLAUDE.md §3b). The board grid:
  **Session verdict** (final action, report status, classification/candidate count/generation/data
  cutoff, why-closed or blocker line), **Authorities** (a four-row gate matrix with LEDs: research,
  buy, brokerage execution, desk status), **Pipeline** (the five stages as one horizontal strip
  with schedule time, terminal state, finish time and plain-English reason), **Attention** (up to
  three incidents inline, the rest behind a disclosure), **Candidates** (a blotter table — symbol,
  action, entry, stop, T1, R:R, conviction — populated ONLY from the current receipt-checked
  report; the overview payload carries no symbols or prices), **Next session** readiness facts,
  **Morning run** telemetry, **System** vitals tiles, and the explicit-save **Note for next
  session**. The **Morning run** panel is the desk's flight recorder for the 05:38-06:20 window:
  the engineering audit's health LED and reliability score, the critical path and the buffer
  remaining to the latest legal freeze, the six scoring components shown as score/max so the
  operator can see *why* the score is what it is (on 2026-08-17 the only deduction was
  `terminal_finality 22/30` — the Preliminary ceiling), the six longest steps, and the full
  stage tape behind a disclosure. Each row's Δ is elapsed-since-the-previous-recorded-event,
  labelled as such: the authoritative per-stage spans live in the audit artifact's
  `critical_path` object, which the console payload does not carry. When no completed audit
  exists the panel says so and shows nothing else — it never invents a score. Engineering health
  never changes market classification or Buy authority. Panels are laid out as two independent
  columns (not aligned grid rows, whose heights vary daily); below 900px they interleave by
  operator priority: verdict, authorities, attention, pipeline, morning run, candidates,
  readiness, system, note. Buy, Watch, Avoid, and
  No Trade classifications keep a neutral treatment; only operational and gate health use status
  colors. With no current receipt-checked report the verdict reads "No verified action", the
  manual-proposal gate stays closed, and the blotter is empty by design.
- **Research**: the in-app reader for the latest receipt-checked morning report — final action,
  Official Research and Buy Authorized flags, generation time, data cutoff, market regime, and
  blocker up top; per-candidate trade tickets grouped into Plan / Catalyst & thesis / Risk /
  Evidence. Downside/risk sections stay visible; supporting report context, Engineering Audit,
  and receipt/hash evidence use native disclosures so the default view remains readable. A
  Buy-flavored candidate action is flagged, not celebrated, unless the report's Buy authority is
  actually granted. A ticket is a proposal, never confirmation that an order exists.
- **History**: history and outcomes from report metadata — counts, never rates, because
  Preliminary sessions can never enter performance statistics (CLAUDE.md §3a): sessions recorded,
  Official, Buy authorized, no-trade outcomes, candidates surfaced, and executed orders
  (permanently 0). A session outcome strip renders one block per session (color = report status,
  height = candidate count, each linking to the dated report page) above the session log table and
  the research-ledger card.
- **Checks**: the six fixed offline checks with the full audit featured, live progress for the
  running check, the operator note queue, and immutable receipt history with copyable
  receipt hashes.
- **System**: six sections — `Health`, `Sources` (lane and provider health), `Research` (model
  inventory and the profitability gate), `Safety` (invariants, release integrity, natural-run
  acceptance, recent activity), `Map` (the compact architecture index, searchable by domain, with
  a copyable context brief), and `Desk feeds` (ledger and journal feed status plus the sanitized
  journal timeline).

Broker-safety copy is fail-closed but honest about which failure it is: a recorded write or
unknown attempt reads "Broker safety violation — review immediately," while incomplete runtime
evidence (for example a receipt-less event log after a killed wrapper) reads "Broker safety
unproven today" — zero writes cannot be verified, so the desk still refuses to show it green.

Morning reports use `/reports/morning/latest`, `/reports/morning`, and
`/reports/morning/YYYY-MM-DD`; the standalone pages share the Research view's renderers. This pivot
does not schedule or send anything and contains no PDF renderer or export endpoint. The view
re-reads local artifacts on a bounded refresh.

Every Morning route preserves two independent layers. **Market Report** shows the receipt-checked
classification, action, Official and Buy fields. **Engineering Audit** shows pending/deferred/
completed/failed state, Green/Amber/Red health, the deterministic 0–100 score and breakdown, stage
timeline, critical path and remaining buffer, supervisor retry class, receipt-bound iteration
status, facts/inferences/unknowns, issue lifecycle, runtime-only remediation, one next improvement,
natural-run trends, and source paths/hashes. Engineering state never alters market fields or grants
Buy/execution authority. Local refresh only rereads files.

### Command palette

`⌘K` / `Ctrl+K` opens a single entry point that filters over the five views, the System sections,
every allowlisted check, and the local display actions (refresh everything, switch light/dark
theme, copy status summary). Text that matches no allowlisted item can only be **staged** in the
Checks note composer; Enter never saves it. The operator must review it and choose **Save note**.
The palette traps focus while open, exposes active-option semantics, returns focus when closed,
and never widens the control boundary. `↑`/`↓` move, `Enter` selects, `Esc` closes.

Every incident and vital is a link to the view that explains it, so the interface is navigable
without knowing the internal component names.

The responsive layout collapses the left rail into a fixed bottom tab bar below 720px and keeps
the decision plus primary attention item in the first mobile viewport without horizontal scroll.
Interactive controls use mobile-safe touch targets. The desk is
dark-first: it opens dark unless an explicit light/dark choice is stored in `localStorage`. The
visual language (2026-08-16) is a quant trading desk: near-black cool ground, hairline panel
chrome, dense 13px type, monospace tabular numerals for every figure and timestamp, uppercase
mono panel headers, and status LEDs; a paper-white daylight theme mirrors the same tokens. The
production client uses locally bundled Lucide icons and no remote assets, satisfying the strict
`script-src 'self'; style-src 'self'` content-security policy (no inline styles or handlers).

The optional compact `/?display=pulse` projection uses the same bundled client and same-origin API.
It omits the check surface entirely, polls the read-only overview and Morning-report endpoints
every 15 seconds, and never adds a new server endpoint or authority path. Its 420×640 view shows
one delivery verdict, literal completed/degraded/skipped/issue counts, the primary attention item,
and only a current report link; unavailable or stale reports and their CTA stay hidden. It shares
the desk's flat panel language (no greeting, no gradients).

## Control Boundary

`config/operator_control.json` is exact and fail-closed. The server recognizes only these action
IDs; the browser cannot provide command text, arguments, paths, or environment values:

| Action | Deterministic purpose |
|---|---|
| `system_integrity_audit` | Check the tracked manifest without rebuilding it |
| `broker_boundary_audit` | Verify preview and mutation tools remain denied |
| `model_governance_audit` | Validate model inventory and architecture context |
| `readiness_contract_audit` | Validate the offline next-session policy contract |
| `console_contract_audit` | Validate console policy, build, context, and loopback configuration |
| `full_offline_audit` | Run all fixed checks sequentially and stop on the first failure |

The control subprocess receives a credential-free environment, uses fixed argv with `shell=False`,
has a 90-second per-step timeout, and cannot invoke network, model, MCP, broker, or financial
execution capabilities. Only one action can run at a time.

Each terminal action creates a mode-`0600`, create-only JSON receipt under the git-ignored
`data/runtime/operator_control/receipts/` directory. A receipt records action identity, timings,
step status, bounded summaries, and SHA-256 hashes of stdout/stderr. Raw command output is not sent
to the browser. Receipt action order, status semantics, safety flags, and artifact hash are
revalidated before display. Invalid, renamed, tampered, or symlinked files are ignored.

## Instruction Queue

The instruction composer — reachable from both the Today and Checks views and from the palette —
stores a normalized local note under `data/runtime/operator_control/instructions/` for a future
agent or human to review. It deliberately does not start a model, workflow, script, or trade.
Queued text grants no approval or authority.

The endpoint accepts one `text` field, limits it to 1,000 characters, collapses whitespace, and
rejects credential-like labels, email addresses, private-key blocks, and long account-number-like
values. Files are mode `0600`, create-only, hash-bound, and git-ignored. Do not paste private data.

## HTTP Security

`config/operator_console.json` (contract `operator_console_policy/1.3`) fixes the service boundary:

- bind address `127.0.0.1` only;
- exact Host allowlist for loopback;
- GET/HEAD for monitoring and POST only for the two fixed control routes;
- same-origin `Origin` and `Sec-Fetch-Site` checks on POST;
- an ephemeral process-local session token returned by the same-origin control-state request;
- JSON-only POST bodies, duplicate-key rejection, and a 4 KiB request limit;
- no CORS, framing, external scripts, external fonts, or external network requests;
- strict CSP, MIME sniffing protection, referrer denial, and same-origin isolation;
- static-file allowlisting, traversal prevention, symlink refusal, and response-size bounds.

The token changes whenever the service restarts and is never written to disk. It protects the local
POST surface from cross-origin browser requests; it is not a remote authentication mechanism. The
service must never be exposed beyond loopback.

API routes:

```text
GET|HEAD /api/v1/health
GET|HEAD /api/v1/overview
GET|HEAD /api/v1/context
GET|HEAD /api/v1/control
GET|HEAD /api/v1/morning-reports
GET|HEAD /api/v1/morning-reports/latest
GET|HEAD /api/v1/morning-reports/YYYY-MM-DD
GET|HEAD /api/v1/ledger
GET|HEAD /api/v1/journal
POST     /api/v1/control/run
POST     /api/v1/control/instructions
```

All other mutation methods and POST paths return `405`. API responses use `no-store`.

## Projections

`GET /api/v1/overview` returns `operator_console_overview/1.2`. It is an aggregate projection:
the general reports list remains category/date/mtime/label/path-hash metadata; research exposes counts
and evidence labels; and account data, prices, prompts, credentials, and raw broker payloads remain
excluded. The separate morning-report API may expose only receipt-checked report fields and approved
sections. It rejects invalid finality, hash drift, ambiguous precedence, unsafe links, and sensitive
content, and always returns both execution flags as false. Executed trades remain deterministically zero.
The embedded engineering object is loaded directly from a validated immutable audit+receipt pair
plus its strict self-hashed observer overlay; the rebuildable history index is not trusted for a
date view. An absent pre-terminal audit displays `PENDING`; a due terminal with no observer or an
invalid observer/audit pair displays `FAILED`. Every condition leaves the market report visible.

The next-session projection accepts only a fully validated `next_session_<target>.json` receipt. It
shows the target, status, safe reason codes, readiness booleans, expected/ready model and connector
counts, continuity state, and blocker/advisory counts. The expected target is re-derived from the
same snapshot clock through `next_session_readiness.resolve_target`: the readiness day rolls at
05:00 PT and then advances through the validated market calendar. Only the receipt for that exact
target is eligible; a stale prior receipt or farther-future receipt never substitutes for a missing
one. The console does not launch live probes.

Historical workflow failures remain critical Desk outcomes even after their root control-plane
fault is repaired. The Safety section keeps the exact release comparison (`match`/`drift` and
reproducibility) separate from runtime-source authority (`match`, validator-approved
`expected_output_drift`, or blocked); safe output drift is visible and is never relabeled as an
exact match. When manifest, documentation, scheduler, runtime binding, and next-session
readiness are current, the headline distinguishes that state as awaiting a future natural run; it
does not erase the failed session or clear its durable attention reasons.

The natural-run projection re-derives v1.1 receipts and rollups from canonical sources. A source-
divergent, future-dated, symlinked, stale, or malformed claim is unavailable. Five eligible sessions
means ready for human review only. Profitability evidence, promotion authority, and production
enforcement remain false.

`GET /api/v1/context` returns the deterministic `agent_context_index/1.0` projection. It provides a
compact Markdown brief and bounded components with source references and local detail commands. It
contains no research conclusions, market data, account data, model output, or runtime artifacts.

### Desk feeds

Two strict-allowlist projections added by the `console_desk_api` pack
(`operator_patches/2026-08-12_console_desk_api/`) feed the History view and System → Desk feeds.
Every string that can reach the wire is validated against a closed token grammar — session dates,
upper/lower snake tokens (≤64 chars), governance versions, and UTC stamps — so free prose, report
paths, hashes, price authorities, emails, and masked account fragments cannot be emitted.

`GET /api/v1/ledger` returns `research_ledger_console/1.0` from the append-only
`data/research_ledger.json`: totals (official research, buy-authorized, preliminary, corrections,
executed orders — deterministically zero) plus the last 20 session rows with date, classification,
and counts-in-metrics. It fails closed as a whole: any malformed row — including a row missing
`execution_enabled: false` or claiming anything else — refuses the entire endpoint with `503`
rather than serving a partial or reinterpreted ledger.

`GET /api/v1/journal` returns `journal_console/1.0` from the append-only
`journal/trading_journal.jsonl`: the last 40 event rows carrying an `event_type`, token fields
only. Journal rows are heterogeneous by design, so non-conforming rows are omitted and counted in
`omitted_event_count`, valid rows beyond the display cap are counted in `capped_event_count`, and
hitting the 4 MB tail window sets `window_truncated` — nothing is dropped silently. A row claiming
`execution_enabled: true` fails the endpoint closed.

The client feature-detects both feeds: against an older server the desk shows a "Server upgrade
pending" card and loses nothing else, and a feed that fails its safety contract is refused, not
partially rendered.

## Service

`com.charles.trading.console` is independent from the scheduled research workflows and watchdog. It
uses `RunAtLoad`, `KeepAlive`, and a 30-second restart throttle. Its runner starts Python under an
empty environment containing only local identity, locale, `HOME`, `PATH`, and unbuffered output. It
does not load project secrets.

Read-only status and contract checks:

```bash
bash scripts/install_operator_console.sh --status
python3 scripts/operator_console.py check
python3 scripts/operator_control.py check
python3 scripts/agent_context.py check
curl --fail http://127.0.0.1:8787/api/v1/health
curl --fail http://127.0.0.1:8787/api/v1/context
```

## Manual Power Action

When the power audit reports a late weekday wake, the console surfaces the audit result only. The
`power` object carries `status`, `required_wake_by_pt`, `observed_wake_pt`, `minutes_after_required`
and `manual_admin_required`; the console renders the status as a single read-only fact tile under
**System → Health**. The console never emits, displays, or copies an admin command — no `pmset`
string exists anywhere in the server, `web/src/main.js`, or the built bundle.

Remediation is an operator action, run by hand in a local terminal:

```bash
sudo pmset repeat wakeorpoweron MTWRF 04:55:00
```

The browser never executes it. macOS administrator review and password entry remain manual.
